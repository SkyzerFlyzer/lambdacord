# SOUL.md

Lambdacord exists because a Discord bot should not need a server. No gateway
websocket to keep alive, no process to babysit, no idle box burning money at
3am waiting for someone to type `/roll`. Discord sends an HTTPS request; a
C++ Lambda wakes, answers, and disappears. Everything in this repository —
every header, script, and convention — follows from taking that model
seriously instead of fighting it.

These are the beliefs the code is built on. When a change feels awkward,
check it against this list; the friction is usually a principle being bent.

## 1. The framework is source, not a service

There is no shared library, no runtime layer, no framework object to link.
`src/include/discord_interactions/` is header-only and compiled into each
Lambda's single `main.cpp`. A Lambda is a self-contained artifact: what you
zip is what runs. This keeps binaries small, cold starts fast, and versioning
trivial — a worker can never disagree with "the framework version deployed
next to it" because there is no such thing.

## 2. Statelessness is honest

In this model there is no session. Each interaction lands on a fresh (or
unrelated warm) container, and the only state Discord will carry back to us
is a component's `custom_id` — 100 bytes, enforced at encode time. We do not
pretend otherwise with in-memory caches that quietly become correctness
dependencies. State that matters lives in module-owned durable storage,
keyed by a compact id that fits the channel. If your design needs more free
state than `custom_id` holds, the design is wrong, not the limit.

## 3. Time is borrowed

Every second a Lambda sleeps is billed, and a sleep past the invocation
deadline kills the run mid-flight — turning one rate-limit into a duplicate
execution. So all in-Lambda waiting is expressed as an explicit budget
clamped to the deadline (AD-8), and the synchronous paths — ingress,
autocomplete, anything on Discord's 3-second clock — never sleep-retry at
all. Retry is a privilege of async workers with time to spend.

## 4. The user always gets an answer

At-least-once delivery means duplicates; failure means retries. The default
posture (AD-9) is the completion marker: record success only *after* the
user-visible PATCH, so a duplicate of a success skips and a retry of a crash
re-runs. A duplicate reply is a papercut; a user stuck forever on
"thinking…" is a broken product. The same instinct shows up everywhere:
durable dedup fails *open*, unknown routes get a clean friendly reply instead
of a silent hang, and transient errors return failure so AWS retries instead
of burning the interaction on a permanent apology. Claim-at-start
at-most-once semantics exist, but only as an explicit opt-in for side effects
that genuinely must not repeat — where a dropped response is the lesser evil.

## 5. Internals never leak

Exception text, upstream API bodies, SDK errors, stack context — none of it
reaches a Discord user, ever. Users get short, friendly, actionable copy
mapped through module-owned allowlists; operators get the real story on
stderr and CloudWatch. These are two different audiences and two different
channels, and crossing them is both a security leak and a UX failure.

## 6. Names are load-bearing

`account link` routes to `discord-cmd-account-link` because the router
derives it, mechanically, every time. Convention is the configuration; there
is no registry to drift out of date. Overrides exist — but as explicit,
validated declarations, never as folklore.

## 7. Generated, not hand-maintained

Anything derivable from module manifests — Terraform wiring, route maps, the
ephemeral-defer allowlist — is generated by a script, committed as clearly
marked generated files, and never edited by hand. Config drift is a class of
bug we chose to delete rather than debug.

## 8. Modules own their world

The framework knows how to verify, route, respond, retry, and dedup. It does
not know what a "nitrado" is. Commands, storage models, external APIs, error
copy, and module Terraform live in `modules/<name>/`, documented in that
module's own docs, deployed from that module's own repo. The root stays
generic so modules can stay sovereign.

## 9. Hermetic builds, fast proofs

Every build runs inside the same Amazon Linux 2023 container that mirrors
the Lambda runtime — no "works on my machine", no local toolchain
requirement. Correctness is proven in layers, fastest first: pure-logic C++
and Python unit tests in seconds, then the full RIE integration harness
against a mock control plane when the change warrants it. A test you can run
in seconds is a test that actually gets run.

## 10. Docs are part of the contract

The architecture decisions above have names (AD-8, AD-9) because they are
written down, and they are written down because unwritten rules die on the
second contributor. Behavior changes ship with their doc updates — README
for the front door, the wiki for depth, `AGENTS.md` for the agent workflow
contract, and module docs for module behavior. If the docs and the code
disagree, that is a bug in the change that split them.
